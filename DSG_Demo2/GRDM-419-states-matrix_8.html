Принцип — 3 канала сигнала

Тело иконки
Зависит от текущего «Highlight by»: Components → цвет = тип; Zones → цвет = зона; None → IEC ч/б. Тип компонента известен всегда — это атрибут модели, а цвет — только режим отображения.
Halo вокруг иконки
Первичное интерактивное состояние: Hover, Selected, Snap-target (Map), In-flight. Один цвет за раз. Работает поверх ЛЮБОГО highlight-режима.
Бейдж + opacity
Validation — стопка бейджей (? / Unlink / ! / counter). DRAFT/Pending = ?. Out-of-scope = opacity + grayscale. Read-only = только cursor: not-allowed.
Интерактивная песочница
Наводи / кликай по элементам. Активные тогглы влияют на сцену.
SLD
2 трансформера, ortho-линия
MAP
3 опоры, polyline
Hover на любом элементе → blue-500 halo (или blue-500 цвет линии). Click → selected (blue-600). «Toggle Warning» добавит оранжевый бейдж на выбранную иконку. Trace mode переключит контекст в инверсию — выбранный элемент остаётся ярким, остальное тускнеет до 30%.

4. Validation — стопка бейджей (до 4 одновременно)

Вместо одного бейджа по приоритету — стопка до 4 одновременных бейджей справа от иконки, по горизонтали. Вокабуляр из 4 элементов: ? HelpCircle (unspecified), Unlink (unbound), ! AlertCircle (warning/error), и Counter (overflow). Info-бейдж в этой системе отсутствует.
Бейдж
SLD (Transformer)
Map (Pole)
? Unspecified
Тип компонента есть, спецификация отсутствует. Grey help-circle.
badge: HelpCircle · neutral-500
Unlink
Компонент существует, но не привязан к графу (нет соединения с противоположной плоскостью). Orange broken-chain.
badge: Unlink · orange-500
! Warning / Error
Жёсткая валидационная проблема — некорректная спецификация, конфликт с правилом, ошибка топологии. Orange alert-circle.
badge: AlertCircle · orange-500
Стэк до 4-х
Несколько проблем одновременно — все бейджи видны. Если проблем больше 3-х уникальных типов или больше нашего бюджета — последний слот занимает Counter (например 9+), сигналящий «есть ещё, открой Info Panel».
stack: 3 badges + counter pill
9+
9+
Правила стопки: бейджи стэкаются горизонтально от верхне-правого угла иконки. Overlap между бейджами: -4px по X. Z-index убывает слева направо (первый бейдж в верхнем z-слое). Максимум 4 слота: при переполнении последний слот — Counter с числом скрытых проблем. Hover на стопке → tooltip со списком всех проблем; click → Info Panel.

5. DRAFT, Read-only, Out-of-scope

Состояние
SLD (Transformer)
Map (Pole)
DRAFT / Pending Specify
Тип компонента известен (трансформер, опора), но спецификация отсутствует. Визуально = ? HelpCircle бейдж (см. блок 4 — Unspecified). Тело иконки в нативном цвете. Различие с другими «?»-проблемами — в тексте в info-panel.
badge: HelpCircle · neutral-500
Read-only
Approved / frozen / вне RBAC-редакторской области. Иконка сохраняет нативный вид. При hover курсор показывает not-allowed, клик игнорируется. Halo и бейджи на ней не появляются — это поведенческий сигнал.
cursor: not-allowed · no halo · no selection
Out-of-scope (RBAC)
Иконка вне текущего scope (проект/зона/фильтр). Ghost-правило: десатурирована до серого + opacity, без hover/click. Применяется единообразно на Map и SLD, к иконкам и линиям.
opacity: 0.35 · grayscale: 1 · pointer-events: none
Read-only: единственный сигнал — поведенческий, через изменение курсора. Графическая модификация иконки отсутствует.

6. Edit-mode (Add / Connect)

Состояние
SLD (Transformer)
Map (Pole)
In-flight
Иконка перетаскивается из палитры. Под иконкой — фоновая плита (--general-background: white в light-теме, black в dark). Весь композит (иконка + плита) на opacity: 0.5.
opacity: 0.5 · bg plate: var(--general-background)
Snap-target · valid
Кандидат для подключения при drag/connect. SLD: подсвечиваются конкретные connection points компонента (точки терминалов на символе). Map: halo вокруг bounding box иконки: на Map компонент рендерится как единый якорь без отдельных терминалов.
SLD: conn-points green-500 · Map: outer halo green-500
Snap-target · warning
Цель допустима, но не идеальна — например, разные voltage-классы, mismatched полярность. Точки/halo в orange-500.
SLD: conn-points orange-500 · Map: outer halo orange-500
Snap-target · error
Цель недопустима — нельзя соединить (несовместимый тип, превышение лимита коннектов). Точки/halo в red-500.
SLD: conn-points red-500 · Map: outer halo red-500
Асимметрия SLD/Map для snap-target: SLD рендерит видимые connection points (терминалы по геометрии символа), Map рендерит компонент как точечный якорь. Поэтому SLD-подсветка локальная (по терминалам), Map-подсветка — на bounding box. Цветовая шкала единая: green / orange / red.

6.1. Snap-target — варианты по классу компонента (SLD)

Число и позиция терминалов берутся из definition компонента (CIM-модель), не хардкодятся в иконке. У большинства — 2 терминала. У 3-обмоточного трансформатора — 3. У шины — переменное, поэтому подсветка работает иначе.
Компонент
Snap-target valid (зелёные точки / halo)
Двухобмоточный трансформатор
Самый частый кейс. 2 терминала: HV сверху, LV снизу. Иконка ⊕⊕ с терминал-линиями.
2 terminals · top + bottom
Трёхобмоточный трансформатор
3 терминала: HV, MV, LV. Обмотки в треугольной композиции, терминалы выходят к трём сторонам символа.
3 terminals · HV / MV / LV
Switch / Breaker / Recloser
2 терминала, на концах горизонтального сегмента. На IEC «открытый» switch — наклонный отрезок между двумя пивотами.
2 terminals · left + right
Busbar (шина)
Переменное число терминалов — появляются в точке, где что-то подключается. Snap-target = вся длина бара как один зелёный halo. Под курсором при drag может появляться «ghost circle» с актуальной X-координатой будущего терминала.
N terminals · highlight: full bar length
Спецификация terminals: число и позиция терминалов на символе компонента — атрибут CIM-модели данных. Канонические размеры визуального компонента — см. блок 6.2 (Figma node 2857:43205): dot 12px, halo 20px. SVG-иллюстрации выше показывают терминалы в уменьшенном масштабе для in-context превью.

6.2. Connection point — состояния и визуальный язык

Принцип: outline / fill различают connectivity-статус, halo различает интерактивный статус, цвет различает snap-validity во время drag-операции. Start-point и end-point визуально не различаются: оба — терминалы; направление связи хранится в данных (CIM), не визуализируется на терминалах.
  • Outline (hollow) = терминал свободен. Совпадает с конвенцией IEC-схематик: открытая точка соединения.
  • Filled (solid) = терминал занят. Совпадает с правилом junction-dot в EE-схемах: filled = connected.
  • Halo = hover ИЛИ snap-target highlight во время активной drag/connect-операции.
  • Цвет: grey/black — default; green — valid snap-target; orange — warning; red — error.
Default
Success
Warning
Error
Outline · unconnected · idle
Outline + halo · hover or snap-active
Filled · connected · idle
Filled + halo · hover on connected
Геометрия (Figma node 2857:43205, на 4px-сетке):
  • Connection dot: diameter 12px (r=6), stroke 1.5px для outline.
  • Halo: diameter 20px (r=10), расширение +4px наружу от dot'а.
  • Drop-shadow на dot'е (Figma shadow-xs): 0 1px 2px #0000000d — мягкая 5% подложка для отлипания от канваса.
Токены (из Figma variables, подтверждены через MCP):
  • Default: stroke general/border · fill general/primary · halo general/border
  • Success: stroke/fill GS-surface/status/success/success default · halo ...success subtle
  • Warning: stroke/fill GS-surface/status/warning/warning default · halo ...warning subtle
  • Error: stroke/fill GS-surface/status/destructive/destructive default · halo ...destructive subtle
Кейсы применения:
  • Idle на канвасе — outline default (свободный) или filled default (занятый).
  • Hover на терминале — outline/filled + default halo.
  • Старт drag-коннекта — все валидные target-терминалы переключаются в success-state (outline + halo).
  • Cursor над warning-target — переключение на warning. Над error-target — error. Drop на error блокируется.
  • Source-терминал во время drag (точка старта) — остаётся filled default (теперь у него in-flight коннект).

8. Connections — состояния соединительных линий

Для линий принцип упрощён: halo не рисуем — для Hover и Selected меняем сам цвет линии. Натив-цвет временно теряется, но это ОК — линия примитивна, её тип читается в info-panel. У линии есть невидимая hit-area — широкая прозрачная зона вокруг (≈12px), чтобы по линии было удобно кликать. Validation — бейджем посередине. DRAFT для линий не применим (тип линии есть в данных всегда), Read-only сохраняет нативный цвет.
Состояние
SLD (прямая, transmission · amber)
Map (curved, distribution · sky)
Default · rest
Цвет линии = тип, толщина 2px. Hit-area: невидимая зона шириной 12px по обе стороны от stroke (показана в превью полупрозрачным серым; в продакшене полностью прозрачна).
stroke: line-type · 2px · hit-area 12px
Hover
Цвет линии меняется на blue-500. Натив-тип временно теряется — это компромисс простоты для элементарного объекта.
stroke: blue-500 · 2px

stroke: blue-600 · 2px

10. Bundle — несколько проводников на одной трассе (Map-only)

На SLD «Single Line» по определению — один логический контур на линию, multi-conductor не применим. На Map 3 фазы на общих опорах (или параллельные фидеры в общей траншее) — реальная задача. Решение: LOD-зависимая отрисовка. На низком зуме — один объект + метка. На высоком — fan-out, каждый проводник кликабельный.
Уровень зума
Сцена (Map · 3 опоры с 3-phase линией)
Low zoom · collapsed
Одна логическая линия + метка 3PH. Толщина чуть больше (3px вместо 2). Клик → дропдаун «выбери проводник: L1 / L2 / L3».
stroke: line-type · 3px · label "3PH"
High zoom · fan-out
На анкерных точках 3 проводника расходятся короткими наклонными сегментами, параллельны в середине пролёта. Каждая линия — самостоятельный элемент с собственным selectable-состоянием. Между фазами зазор ≈6px.
spread at anchors · parallel mid-span · 6px gap
Fan-out с одной выбранной
L2 (средняя фаза) выбрана — её цвет blue-600, толщина 2px. Остальные две — натив. Клик по любой переключает выбор на неё.
selected: blue-600 · 2px · others: native
Переход между LOD-уровнями: FE определяет режим рендеринга по текущему zoom-level. Спецификация фиксирует визуальный язык каждого уровня (collapsed / fan-out / промежуточный) и правила переходов; конкретные пороги zoom калибруются на production-данных и не входят в дизайн-спеку.
